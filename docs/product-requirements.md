# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**toto GOAL3 Predictor** - 機械学習ベースのtoto GOAL3購入戦略システム

### プロダクトコンセプト
- **データドリブンな予測**: Wyscoutの高度なサッカー統計データと機械学習モデルを組み合わせ、各チームの得点分布を科学的に予測
- **バリューベット特定**: モデル予測確率と公衆投票率のギャップを分析し、期待値がプラスとなるバリューベットを自動特定
- **自動化されたパイプライン**: データ収集から予測、購入推奨までを自動化し、週次の運用負荷を最小化

### プロダクトビジョン
サッカーの試合データを科学的に分析し、toto GOAL3における期待値の高い購入戦略を提供する。感覚や経験則に頼らず、データに基づいた意思決定を可能にすることで、長期的なROIの向上を目指す。公衆投票率との乖離を活用し、市場の非効率性から価値を見出すアプローチを実現する。

### 目的
- Jリーグの試合データを活用した高精度な得点分布予測モデルの構築
- 公衆投票率とモデル予測のギャップからバリューベットを自動特定
- データ収集から購入推奨までの週次パイプラインの自動化
- 長期的なROI向上（目標: プラス収支の維持）

## ターゲットユーザー

### プライマリーペルソナ: 山田健一（35歳、データサイエンティスト/toto愛好家）
- **属性**: IT企業勤務、データ分析の専門知識あり、Jリーグファン歴10年以上
- **toto経験**: 月に2-4回程度購入、年間投資額は5-10万円程度
- **現在の課題**:
  - 感覚的な予測に限界を感じている
  - 投票率だけを見ても期待値が判断できない
  - 週末ごとの分析に時間がかかりすぎる
- **期待する解決策**: データに基づいた購入判断の自動化、バリューベットの可視化
- **1日の典型的なワークフロー（試合週末）**:
  1. 金曜夜: 対象試合のチーム情報を確認
  2. 土曜午前: 投票率を確認し購入判断
  3. 土曜午後: 購入実行
  4. 日曜: 結果確認、次回に向けた振り返り

### セカンダリーペルソナ: 佐藤翔太（28歳、一般会社員/カジュアルtotoプレイヤー）
- **属性**: totoを月1回程度購入、詳細な分析は行わない
- **現在の課題**: 何を買えばいいか判断基準がない
- **期待する解決策**: シンプルな購入推奨（「今週はこれを買え」レベル）

## 成功指標(KPI)

### プライマリーKPI
- **モデル精度 - Brier Score**: 0.20未満（運用開始3ヶ月後）
  - 測定方法: 全予測の確率スコアを計算し平均
- **モデル精度 - カテゴリ的中率**: 40%以上（運用開始3ヶ月後）
  - 測定方法: 最頻予測カテゴリと実際の結果の一致率
- **長期ROI**: 0%以上（運用開始6ヶ月後、100回以上の購入後）
  - 測定方法: (累計払戻金額 - 累計購入金額) / 累計購入金額

### セカンダリーKPI
- **バリューベット的中率**: 一般的な的中率より10ポイント以上高い
  - ベースライン: ランダム予測の期待的中率 25%（4カテゴリ均等）
  - 目標: 35%以上
  - 測定方法: バリュースコア1.5以上で購入した場合の的中率
- **パイプライン稼働率**: 95%以上（週次バッチ処理の成功率）
  - ベースライン: 初期運用では80%程度を想定
  - 目標: 運用3ヶ月後に95%以上
  - 測定方法: 自動実行の成功/失敗ログから計算
- **予測キャリブレーション**: 予測確率と実際の発生確率の差が±5%以内
  - ベースライン: キャリブレーション前は±15%程度の乖離を想定
  - 目標: ±5%以内
  - 測定方法: 確率帯ごとの的中率を集計（0-10%, 10-20%, ..., 90-100%）

## 機能要件

### コア機能(MVP)

#### 1. データ収集パイプライン

**前提条件**:
- Wyscoutからの試合データは**手動でダウンロード**し、`data/wyscout/{season}/`ディレクトリに配置する
- Wyscout APIによる自動取得はスコープ外（将来対応の可能性あり）
- Excelファイル形式: `Team Stats {チーム名}.xlsx`（Wyscoutのデフォルト出力形式）

**ユーザーストーリー**:
データサイエンティストとして、Wyscoutからダウンロードした最新試合データを取り込むために、データ収集パイプラインが欲しい

**受け入れ条件**:
- [ ] `data/wyscout/{season}/`フォルダ内のExcel(.xlsx)ファイルを読み込み、標準化された形式でローカルDBに保存できる
- [ ] J1/J2リーグのチームデータを処理できる
- [ ] 週次で新規データを追加取り込みできる（差分更新）
- [ ] 過去2シーズン分（約700試合）のデータを保持できる
- [ ] ファイル形式エラー時に明確なエラーメッセージを出力する

**例外処理方針**:

| シナリオ | 処理方針 | ユーザー通知 |
|---------|---------|-------------|
| ファイル形式エラー（非xlsx） | スキップして継続 | 警告ログ出力 |
| 必須カラム欠落 | スキップして継続 | 警告ログ出力、欠落カラム名を明示 |
| データ型エラー（数値に文字列） | 該当行をスキップ | 警告ログ出力、行番号を明示 |
| 重複データ | スキップして継続 | 情報ログ出力 |
| 空ファイル | スキップして継続 | 警告ログ出力 |
| ディレクトリ内にファイルなし | エラー終了 | エラーメッセージ出力 |
| 全ファイル処理失敗 | エラー終了 | エラーメッセージ出力、詳細ログ参照を促す |

> **ベストエフォート方針**: 部分的なエラーでも処理可能なデータは取り込み、最終的に取り込み結果サマリーを出力する。

**優先度**: P0(必須)

#### 2. 特徴量エンジニアリング

**ユーザーストーリー**:
データサイエンティストとして、生データから予測に有効な特徴量を生成するために、特徴量エンジニアリング機能が欲しい

**受け入れ条件**:
- [ ] 基本統計特徴量（xG, Goals, Shots on targetなど）を計算できる
- [ ] 直近N試合（5, 10, 20試合）のウィンドウ統計を生成できる
- [ ] 高度な派生特徴量（shot_conversion, xG_overperformanceなど）を計算できる
- [ ] 対戦相手の特徴量を考慮した調整特徴量を生成できる
- [ ] 特徴量は50種類以上を生成できる

**優先度**: P0(必須)

#### 3. 得点分布予測モデル

**ユーザーストーリー**:
データサイエンティストとして、各チームの得点確率分布を予測するために、機械学習モデルが欲しい

**受け入れ条件**:
- [ ] Poisson Regressionによるベースラインモデルを実装できる
- [ ] XGBoostによるメインモデルを実装できる
- [ ] アンサンブルモデル（重み付き平均）を構築できる
- [ ] totoカテゴリ（0点, 1点, 2点, 3点以上）の確率を出力できる
- [ ] キャリブレーション（Platt Scaling / Isotonic Regression）を適用できる
- [ ] 時系列CVによる検証でBrier Score 0.20未満を達成できる

**優先度**: P0(必須)

#### 4. 投票率スクレイピング

**ユーザーストーリー**:
データサイエンティストとして、公衆投票率を自動取得するために、Webスクレイパーが欲しい

**受け入れ条件**:
- [ ] totoONE（https://www.totoone.jp/prediction）から投票率を取得できる
- [ ] GOAL3の6チーム分のデータを正確にパースできる
- [ ] 各カテゴリ（0点, 1点, 2点, 3点以上）の投票率を抽出できる
- [ ] スクレイピング失敗時にリトライ（3回まで）を実行できる
- [ ] サイト構造変更を検知しアラートを発行できる

**リトライ戦略詳細**:

| パラメータ | 値 | 説明 |
|-----------|---|------|
| 最大リトライ回数 | 3回 | 初回含め最大4回試行 |
| 初期待機時間 | 1秒 | 最初のリトライ前の待機 |
| 待機時間増加 | 指数バックオフ | 1s → 2s → 4s |
| 最大待機時間 | 4秒 | |
| タイムアウト | 30秒 | 1回のリクエストのタイムアウト |
| 総タイムアウト | 120秒 | 全リトライ含む最大処理時間 |

**リトライ対象エラー**:
- ネットワークタイムアウト
- HTTP 5xx エラー（サーバーエラー）
- 接続エラー

**即時失敗（リトライしない）エラー**:
- HTTP 4xx エラー（クライアントエラー）
- パース失敗（HTML構造が変更された可能性）
- 認証エラー

**フォールバック戦略**:
1. リトライ上限到達 → 警告出力、前回取得データを使用（存在する場合）
2. 前回データなし → エラー終了、手動での投票率入力を促す

**優先度**: P0(必須)

#### 5. バリュースコア計算・購入推奨

**ユーザーストーリー**:
toto購入者として、どの選択肢がバリューなのか判断するために、バリュースコアと購入推奨が欲しい

**受け入れ条件**:
- [ ] バリュースコア（モデル確率 / 投票率）を全選択肢について計算できる
- [ ] 購入判断マトリクス（モデル確率 × バリュースコア）に基づいて推奨を出力できる
- [ ] Kelly Criterionに基づく推奨ベットサイズを計算できる
- [ ] 推奨結果をMarkdown形式でレポート出力できる

**優先度**: P0(必須)

### CLIインターフェース

```bash
# データ取り込み（wyscout_data/フォルダ内のExcelファイルを読み込み）
toto-predictor import --dir wyscout_data/

# 特徴量生成
toto-predictor features --team "横浜FM" --window 10

# モデル学習
toto-predictor train --model xgboost --cv 5

# 予測実行
toto-predictor predict --round 1607

# 投票率取得
toto-predictor scrape --source totoone

# 戦略実行（予測 + 投票率 + バリュー計算 + 推奨出力）
toto-predictor strategy --round 1607 --output report.md

# パイプライン全体実行（週次運用）
toto-predictor pipeline --round 1607
```

## 非機能要件

### パフォーマンス
- **モデル推論時間**: 6チーム分の予測を10秒以内で完了
- **特徴量生成時間**: 1チーム分の特徴量生成を5秒以内で完了
- **スクレイピング時間**: 投票率取得を30秒以内で完了

### ユーザビリティ
- **CLIヘルプ**: `--help` オプションで全コマンドの使用方法を確認できる
- **エラーメッセージ**: エラー発生時に原因と対処法を明示する
- **ログ出力**: 処理進捗をリアルタイムでログ出力する

### 信頼性
- **データ整合性**: データベースへの書き込みはトランザクションで保護
- **バックアップ**: モデルファイルと予測結果は日次で自動バックアップ
- **リトライ機構**: 外部API/Webアクセス失敗時は3回までリトライ

### セキュリティ
- **認証情報管理**: APIキー等は環境変数または`.env`ファイルで管理
- **スクレイピング倫理**: robots.txtを遵守、適切なリクエスト間隔（1秒以上）を設定

### スケーラビリティ
- **データ量**: 過去5シーズン分（約2,500試合）まで拡張可能な設計
- **リーグ拡張**: J2リーグ等への拡張を考慮した設計（将来対応）

## スコープ外

明示的にスコープ外とする項目:
- **toto BIG/mini toto**: GOAL3以外のtoto商品は対象外
- **海外リーグ**: Jリーグ以外のリーグは対象外
- **自動購入実行**: MVP段階では購入推奨の出力までとし、実際の購入操作は手動
- **リアルタイムオッズ変動対応**: 締切直前のオッズ変動への動的対応は対象外
- **モバイルアプリ**: ネイティブアプリは対象外（CLIツールとして提供）
